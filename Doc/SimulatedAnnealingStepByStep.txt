WHAT IS SIMULATED ANNEALING?
-----------------------------
Simulated Annealing is inspired by the physical process of heating and slowly
cooling metal to remove defects and reach a low-energy stable state.

In optimization:
- High temperature = Explore freely (accept worse moves)
- Low temperature = Exploit current best (accept only better moves)
- Cooling down gradually = Transition from exploration to exploitation

For 8-Puzzle: Find the sequence of moves to reach the goal state from initial
state by intelligently exploring the search space.

LINES 30-38: ACCEPTANCE PROBABILITY FUNCTION
================================================================================

Line: double acceptanceProbability(int currentH, int nextH, double temperature)
What it does: Calculate probability of accepting a move
Parameters:
  - currentH: Heuristic of current state
  - nextH: Heuristic of neighbor state
  - temperature: Current temperature value
Returns: Probability between 0 and 1
Why: Determines whether to accept worse solutions

Line: if (nextH < currentH)
What it does: Check if neighbor is better than current
Why: If better, we always want to accept it

Line: return 1.0;
What it does: Return 100% acceptance probability
Why: Always accept improvements

Line: int deltaE = nextH - currentH;
What it does: Calculate energy difference (how much worse)
Why: Need this for probability formula

Line: return exp(-deltaE / temperature);
What it does: Calculate Boltzmann probability
Formula breakdown:
  - deltaE: How much worse the move is (positive value)
  - temperature: Current temperature
  - -deltaE/temperature: Negative ratio (becomes more negative as T drops)
  - exp(...): Exponential function
  
Behavior:
  - High temperature: exp(-small negative) ≈ high probability
  - Low temperature: exp(-large negative) ≈ low probability
  - Larger deltaE: Lower probability (worse moves less likely)

Example:
  deltaE = 2 (neighbor is 2 worse)
  temperature = 100
  Probability = e^(-2/100) = e^(-0.02) ≈ 0.98 (98% chance)
  
  deltaE = 2 (same difference)
  temperature = 1
  Probability = e^(-2/1) = e^(-2) ≈ 0.135 (13.5% chance)

================================================================================
HOW THE ALGORITHM WORKS - COMPLETE FLOW
================================================================================

INITIALIZATION PHASE:
1. Read initial puzzle state from file
2. Read goal state from file
3. Set temperature = 100.0 (hot, exploratory)
4. Set cooling rate = 0.995
5. Set iteration counter = 1

MAIN LOOP (Repeat until frozen or goal found):

  STEP 1: Evaluate current state
    - Calculate Manhattan distance (h)
    - If h = 0, goal found → STOP
  
  STEP 2: Generate possible moves
    - Find blank tile position
    - Try move up (if possible)
    - Try move down (if possible)
    - Try move left (if possible)
    - Try move right (if possible)
    - Result: 2-4 neighbor states
  
  STEP 3: Select random neighbor
    - Pick random move from possible moves
    - This is key difference from Hill Climbing
  
  STEP 4: Calculate energy difference
    - Evaluate neighbor's heuristic
    - Compute deltaE = nextH - currentH
    - Negative deltaE = improvement
    - Positive deltaE = worsening
  
  STEP 5: Decide whether to accept move
    - If improvement (deltaE < 0): Always accept
    - If worsening (deltaE > 0):
      * Calculate prob = e^(-deltaE/T)
      * Generate random number
      * Accept if prob > random
      * Higher temp → higher acceptance rate
      * Lower temp → lower acceptance rate
  
  STEP 6: Update state (if accepted)
    - Move to neighbor state
    - Or stay at current state (if rejected)
  
  STEP 7: Cool down
    - Reduce temperature: T = T * 0.995
    - Next iteration will be "cooler"
    - Gradually reduces exploration
  
  STEP 8: Increment iteration counter
    - Track progress
    - Check against max iterations

TERMINATION:
  - Goal found (h = 0): Success!
  - Temperature too low: System frozen
  - Max iterations: Gave up
  - Display final state and statistics


================================================================================
WHY SIMULATED ANNEALING WORKS
================================================================================

THE PROBLEM WITH HILL CLIMBING:
- Always takes best move
- Gets stuck in local optima
- Can't escape "valleys"

THE SOLUTION - SIMULATED ANNEALING:
- Sometimes accepts worse moves
- High temperature: Accept most worse moves (explore freely)
- Low temperature: Accept few worse moves (exploit current best)
- Cooling schedule: Gradual transition from exploration to exploitation

KEY INSIGHT:
- Early: Wander freely, escape local optima
- Late: Focus on refining current solution
- Balance: Controlled by temperature and cooling rate

ANALOGY:
Like finding the lowest point in a landscape:
- Hot: Jump around randomly, explore widely
- Cooling: Jump smaller, explore locally
- Cold: Settle into nearest valley
- Goal: Find global minimum, not just local


================================================================================
PARAMETER EFFECTS
================================================================================

INITIAL TEMPERATURE (100.0):
- Too low: Acts like greedy search, gets stuck
- Too high: Too random, wastes time
- Sweet spot: 10-1000 depending on problem

COOLING RATE (0.995):
- Too fast (0.9): Freezes before exploring enough
- Too slow (0.999): Takes too long to converge
- Sweet spot: 0.95-0.999

MIN TEMPERATURE (0.01):
- Too high: Stops before converging
- Too low: Unnecessary iterations
- Sweet spot: 0.001-0.1

MAX ITERATIONS (10000):
- Safety net to prevent infinite loops
- Should be high enough to allow convergence
