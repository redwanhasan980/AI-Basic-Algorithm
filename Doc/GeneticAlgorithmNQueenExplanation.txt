WHAT IS THE N-QUEEN PROBLEM?
-----------------------------
The N-Queen problem is a classic puzzle: Place N chess queens on an N×N 
chessboard so that no two queens threaten each other.

Queens can attack:
- Horizontally (same row)
- Vertically (same column)
- Diagonally (in both diagonal directions)

For example, with N=8, you need to place 8 queens on an 8×8 board such that
none of them can attack any other queen.


WHAT IS A GENETIC ALGORITHM?
-----------------------------
A Genetic Algorithm (GA) is inspired by natural evolution and Darwin's theory
of "survival of the fittest."

The idea:
1. Start with a population of random solutions
2. Keep the good solutions (high fitness)
3. Combine good solutions to create new ones (crossover)
4. Add small random changes (mutation)
5. Repeat until you find the perfect solution

It's like breeding plants or animals - keep the best traits and pass them on
to the next generation!


WHY USE GENETIC ALGORITHM FOR N-QUEEN?
---------------------------------------
- Traditional backtracking becomes very slow for large N (N > 20)
- Genetic Algorithm can find solutions faster for large N
- It explores multiple solutions simultaneously (population-based)
- Good for problems where exact algorithms are too slow
- Can find "good enough" solutions quickly even if perfect solution is hard


KEY CONCEPTS AND TERMINOLOGY
=============================

1. CHROMOSOME (INDIVIDUAL)
   - One possible solution to the problem
   - For N-Queen: An array of N integers
   - Each position represents a column
   - The value represents which row the queen is in
   - Example: [2, 0, 3, 1] means:
     * Column 0: Queen at row 2
     * Column 1: Queen at row 0
     * Column 2: Queen at row 3
     * Column 3: Queen at row 1

2. POPULATION
   - A collection of many chromosomes (individuals)
   - Like a community where solutions compete
   - Typical size: 50-200 individuals
   - More population = more diversity, but slower

3. FITNESS
   - A score measuring how good a solution is
   - Higher fitness = better solution
   - For N-Queen: Count non-attacking queen pairs
   - Maximum fitness = N*(N-1)/2 (no attacks at all)
   - Example: 8 queens, max fitness = 28 pairs

4. GENERATION
   - One iteration of the evolution process
   - Like one breeding cycle in nature
   - Each generation creates new offspring from parents

5. SELECTION
   - Choosing which individuals become parents
   - Better fitness = higher chance of being selected
   - "Survival of the fittest" in action

6. CROSSOVER (RECOMBINATION)
   - Combining two parent chromosomes to create a child
   - Child inherits traits from both parents
   - Like mixing genes in biological reproduction

7. MUTATION
   - Random small changes to a chromosome
   - Prevents getting stuck in local optima
   - Adds diversity to the population
   - Like random genetic mutations in nature

8. ELITISM
   - Keeping the best individuals unchanged
   - Ensures we don't lose the best solutions
   - Typically keep top 10% of population


CHROMOSOME REPRESENTATION EXPLAINED
====================================

Why use an array of integers?

Each index (position in array) = Column number
Each value = Row number where queen is placed

Example for N=4:
Chromosome: [1, 3, 0, 2]

Visual representation:
  Col:  0  1  2  3
       -----------
Row 0:  .  .  Q  .
Row 1:  Q  .  .  .
Row 2:  .  .  .  Q
Row 3:  .  Q  .  .

Reading the chromosome:
- chromosome[0] = 1 → Queen in column 0, row 1
- chromosome[1] = 3 → Queen in column 1, row 3
- chromosome[2] = 0 → Queen in column 2, row 0
- chromosome[3] = 2 → Queen in column 3, row 2

This representation automatically ensures:
- Only one queen per column (each index appears once)
- But may have multiple queens per row or diagonal (needs fixing)


FITNESS FUNCTION - THE EVALUATION SYSTEM
=========================================

The fitness function determines how good a solution is.

Goal: Maximize the number of non-attacking queen pairs.

Maximum possible pairs = N * (N-1) / 2
- For 4 queens: 4 * 3 / 2 = 6 pairs
- For 8 queens: 8 * 7 / 2 = 28 pairs

How to calculate:
1. Count all pairs of queens that attack each other
2. Subtract from maximum possible pairs
3. Result = number of non-attacking pairs

Types of attacks to check:

1. HORIZONTAL ATTACK (Same Row)
   - If chromosome[i] == chromosome[j], they're in the same row
   - Example: [2, 1, 2, 0] → columns 0 and 2 both at row 2

2. DIAGONAL ATTACK
   - If the difference in rows equals difference in columns
   - Formula: |chromosome[i] - chromosome[j]| == |i - j|
   - Example: 
     * Queen at (col=0, row=1)
     * Queen at (col=2, row=3)
     * Row difference: |1-3| = 2
     * Column difference: |0-2| = 2
     * They're on the same diagonal!

3. NO VERTICAL ATTACKS
   - Our representation prevents this automatically
   - Each queen has its own column


STEP-BY-STEP ALGORITHM IMPLEMENTATION
======================================

PART 1: SETUP AND CONSTANTS
----------------------------

Step 1: Define algorithm parameters
   - POPULATION_SIZE: Number of individuals in each generation
     * Typical values: 50-200
     * Larger = more diversity, but slower
     * We use 100 as a good balance
   
   - MAX_GENERATIONS: Maximum iterations before giving up
     * Typical values: 1000-10000
     * Prevents infinite loops
     * We use 10000 to give enough time
   
   - MUTATION_RATE: Probability of mutation per gene
     * Typical values: 0.01 to 0.2 (1% to 20%)
     * Too low = gets stuck (no diversity)
     * Too high = too random (loses good traits)
     * We use 0.1 (10%) as a balanced rate

Step 2: Create Individual structure
   - Contains two things:
     * chromosome: vector of integers (the solution)
     * fitness: integer score (how good it is)
   - This bundles solution and its quality together


PART 2: FITNESS CALCULATION
----------------------------

Step 3: Write the fitness function

Input: A chromosome (vector of integers)
Output: Fitness score (integer)

3a. Initialize attack counter to 0

3b. Get the size of the board (N)

3c. Loop through all pairs of queens
    - Outer loop: i from 0 to N-1
    - Inner loop: j from i+1 to N-1
    - This checks each pair exactly once

3d. For each pair (i, j):
    Check if they attack each other
    
    Horizontal attack:
    - If chromosome[i] == chromosome[j]
    - Increment attacks counter
    
    Diagonal attack:
    - If absolute value of (chromosome[i] - chromosome[j]) 
      equals absolute value of (i - j)
    - Increment attacks counter

3e. Calculate fitness
    - Maximum possible pairs = N * (N-1) / 2
    - Fitness = Maximum pairs - attacks
    - Return fitness
    
    Why this formula?
    - We want to maximize non-attacking pairs
    - Higher fitness = fewer attacks = better solution
    - Perfect solution has fitness = maximum pairs


PART 3: POPULATION INITIALIZATION
----------------------------------

Step 4: Create a single random individual

4a. Create new Individual object

4b. Initialize chromosome with size N

4c. Fill chromosome randomly
    - For each position i from 0 to N-1:
    - Set chromosome[i] = random number between 0 and N-1
    - This places queen randomly in each column

4d. Calculate fitness
    - Call fitness function on this chromosome
    - Store result in individual's fitness field

4e. Return the individual

Step 5: Create initial population

5a. Create empty population vector

5b. Loop POPULATION_SIZE times
    - Create a random individual
    - Add it to population vector

5c. Return the population

Why random initialization?
- Ensures diversity
- Explores different parts of solution space
- Some might be close to solution by luck


PART 4: PARENT SELECTION
-------------------------

Step 6: Implement tournament selection

Purpose: Choose good individuals to be parents
Method: Tournament selection (simple and effective)

6a. Randomly pick two individuals from population
    - Get random index1: any number from 0 to POPULATION_SIZE-1
    - Get random index2: any number from 0 to POPULATION_SIZE-1
    - Can be same or different

6b. Compare their fitness
    - If individual1.fitness > individual2.fitness
    - Return individual1
    - Otherwise, return individual2

Why tournament selection?
- Simple to implement
- Better individuals have higher chance of being selected
- Still gives weaker individuals a small chance (diversity)
- Doesn't need fitness proportional selection (simpler math)


PART 5: CROSSOVER (BREEDING)
-----------------------------

Step 7: Combine two parents to create offspring

Purpose: Mix good traits from two parents
Method: Single-point crossover

7a. Get the chromosome size (N)

7b. Create new child Individual

7c. Initialize child's chromosome with size N

7d. Choose random crossover point
    - Pick random position from 0 to N-1
    - This is where we'll "cut" the chromosomes

7e. Copy first part from parent1
    - For positions 0 to crossoverPoint-1
    - child.chromosome[i] = parent1.chromosome[i]

7f. Copy second part from parent2
    - For positions crossoverPoint to N-1
    - child.chromosome[i] = parent2.chromosome[i]

7g. Calculate child's fitness
    - Call fitness function on child's chromosome

7h. Return the child

Visual example with N=4 and crossoverPoint=2:
Parent1:  [1, 3, 0, 2]
Parent2:  [2, 0, 3, 1]
          ^     ^
          |     crossover point
Child:    [1, 3, 3, 1]
          ----  ----
          from  from
          P1    P2

Why crossover?
- Combines good parts from both parents
- Child might be better than either parent
- Explores new combinations of traits


PART 6: MUTATION
-----------------

Step 8: Apply random changes to maintain diversity

Purpose: Introduce random variation
Method: Gene-by-gene random mutation

8a. Get chromosome size (N)

8b. For each gene (position) in chromosome
    - Loop i from 0 to N-1

8c. For each gene, decide whether to mutate
    - Generate random number between 0 and 1
    - If random number < MUTATION_RATE:
      * Replace chromosome[i] with random value (0 to N-1)
      * This changes where the queen is placed in that column

8d. Recalculate fitness after mutation
    - Chromosome changed, so fitness needs updating
    - Call fitness function

Why mutation?
- Prevents premature convergence (getting stuck)
- Introduces new genetic material
- Helps escape local optima
- Explores solutions that crossover alone can't reach

Mutation rate balance:
- Too low (1%): Population becomes too similar, gets stuck
- Too high (50%): Too random, loses good solutions
- Sweet spot (10%): Balance between stability and exploration


PART 7: CREATING NEXT GENERATION
---------------------------------

Step 9: Evolve the population

9a. Sort population by fitness (best first)
    - Highest fitness at index 0
    - Lowest fitness at end
    - This identifies the best solutions

9b. Check for perfect solution
    - If best individual's fitness == maximum possible fitness
    - Solution found! Mark as solved and stop

9c. Initialize empty new population

9d. Implement Elitism
    - Calculate elite count (top 10% of population)
    - Copy the best individuals directly to new population
    - No changes to these - guaranteed to survive
    - Why? Don't want to lose best solutions we've found

9e. Fill rest of new population through evolution
    - While new population size < POPULATION_SIZE:
      
      * Select first parent using tournament selection
      * Select second parent using tournament selection
      * Create child through crossover of both parents
      * Apply mutation to the child
      * Add child to new population

9f. Replace old population with new population

9g. Increment generation counter

This is one complete generation!


PART 8: MAIN ALGORITHM LOOP
----------------------------

Step 10: Set up the algorithm

10a. Seed random number generator
     - Use current time as seed
     - Ensures different results each run

10b. Get N from user
     - Ask: "Enter N: "
     - Read integer value
     - This is the board size

10c. Calculate maximum fitness
     - maxFitness = N * (N-1) / 2
     - This is the target we're trying to reach

10d. Print algorithm information
     - Display N-Queen problem
     - Show maximum fitness value

Step 11: Initialize population
     - Call createPopulation function
     - Creates POPULATION_SIZE random individuals
     - Each with random queen placements

Step 12: Initialize loop variables
     - generation counter = 0
     - solutionFound flag = false

Step 13: Main evolution loop
     - Continue while:
       * generation < MAX_GENERATIONS (haven't given up yet)
       * AND solutionFound is false (haven't found solution)

Step 14: Inside the loop, do evolution (as described in Step 9)

Step 15: Progress reporting
     - Every 100 generations:
       * Print generation number
       * Print best fitness so far
       * Shows user the algorithm is working

Step 16: After loop ends, handle results

     If solution found:
     - Print success message with generation number
     - Display the solution board visually
     - Show queen positions
     
     If no solution found:
     - Print "no perfect solution" message
     - Display best result achieved
     - Show fitness score


PART 9: DISPLAYING THE SOLUTION
--------------------------------

Step 17: Print the board and solution

17a. Get board size (N)

17b. Print header

17c. Draw the board
     - For each row (0 to N-1):
       * For each column (0 to N-1):
         - If chromosome[column] == row:
           Print "Q " (queen here)
         - Otherwise:
           Print ". " (empty square)
       * Print newline after each row

17d. Print queen positions as coordinates
     - For each column:
       * Print (column, chromosome[column])
     - This shows (col, row) for each queen

Visual example output for N=4 solution [1, 3, 0, 2]:
. . Q . 
Q . . . 
. . . Q 
. Q . . 

Queen positions (col, row): (0,1) (1,3) (2,0) (3,2)


HOW THE ALGORITHM WORKS - BIG PICTURE
======================================

Generation 0 (Initial):
- Create 100 random solutions
- Most are terrible (many attacks)
- Few might be slightly better by chance

Generation 1-10:
- Best solutions survive (elitism)
- Good solutions breed with each other
- Children inherit good traits
- Mutations add new variations
- Average fitness increases

Generation 11-100:
- Population gets better and better
- Attacks decrease
- Queens start avoiding each other
- Solutions converge toward optimum

Generation 100-500:
- Fine-tuning phase
- Small improvements
- May find perfect solution
- Or get very close

Why it works:
1. Selection pressure pushes toward better solutions
2. Crossover combines good traits
3. Mutation explores new possibilities
4. Elitism preserves progress
5. Over time, population evolves toward optimum

PARAMETER TUNING GUIDE
=======================

POPULATION_SIZE:
- Too small (< 50): Limited diversity, gets stuck
- Too large (> 500): Slow, wastes computation
- Recommended: 50-200
- For N-Queen: 100 works well

MAX_GENERATIONS:
- Too small (< 100): Might not find solution
- Too large (> 50000): Wastes time if no solution exists
- Recommended: 1000-10000
- For N-Queen: 10000 gives good chances

MUTATION_RATE:
- Too low (< 0.01): No diversity, gets stuck in local optimum
- Too high (> 0.3): Too random, can't converge
- Recommended: 0.05-0.15
- For N-Queen: 0.1 (10%) balances exploration and exploitation

ELITISM (top percentage kept):
- Too low (< 5%): Might lose best solutions
- Too high (> 30%): Reduces diversity, slows evolution
- Recommended: 5-15%
- For N-Queen: 10% preserves best while allowing evolution


WHY GENETIC ALGORITHM WORKS FOR N-QUEEN
========================================

Advantages:
1. Scales well to large N (N > 50)
2. Can find solutions quickly (often under 1000 generations)
3. Doesn't need domain-specific knowledge
4. Parallelizable (can evaluate fitness in parallel)
5. Can provide "good enough" solutions if perfect is hard

Disadvantages:
1. Not guaranteed to find solution
2. Randomness means different results each run
3. May take many generations
4. Tuning parameters requires experimentation

When to use:
- N > 20 (where backtracking gets slow)
- When approximate solution is acceptable
- When you want to experiment with evolution
- When traditional methods fail


COMPARISON WITH OTHER METHODS
==============================

BACKTRACKING:
- Guaranteed to find solution if exists
- Very slow for large N (exponential time)
- N=20: can take hours
- Deterministic (always same result)

GENETIC ALGORITHM:
- Fast even for large N (polynomial time)
- Not guaranteed to find solution
- N=100: can solve in minutes
- Randomized (different results each time)

HILL CLIMBING:
- Faster than GA
- Gets stuck in local optima easily
- Needs good starting point
- Single solution at a time

SIMULATED ANNEALING:
- Similar to GA but single solution
- Good at escaping local optima
- Slower than GA for N-Queen
- Requires temperature schedule tuning


COMMON MISTAKES TO AVOID
=========================

1. Not initializing random seed
   - Always call srand(time(0)) at start
   - Otherwise same results every time

2. Fitness function errors
   - Make sure to check ALL attack types
   - Don't count same pair twice
   - Formula should be maxPairs - attacks

3. Forgetting to recalculate fitness
   - After crossover: calculate child fitness
   - After mutation: recalculate fitness
   - Fitness must match chromosome

4. Wrong mutation rate
   - 0.1 is good starting point
   - Don't use 1.0 (100% mutation is chaos!)
   - Don't use 0.0 (no diversity)

5. Not using elitism
   - Always keep best solutions
   - 10% is a good amount
   - Prevents losing progress

6. Infinite loops
   - Always have MAX_GENERATIONS limit
   - Check for solution found condition
   - Print progress to debug

7. Wrong crossover point
   - Should be random between 0 and N-1
   - Not always same position
   - Creates diversity in offspring
