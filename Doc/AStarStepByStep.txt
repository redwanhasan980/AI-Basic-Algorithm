WHAT IS A* ALGORITHM?
---------------------
A* is an informed search algorithm that finds the shortest path between two
nodes in a graph. It's "informed" because it uses a heuristic function to
guide the search toward the goal efficiently.

A* combines:
- g(n): Actual cost from start to current node (like Dijkstra)
- h(n): Estimated cost from current node to goal (heuristic)
- f(n): g(n) + h(n) - Total estimated cost through this node

Key advantage: Finds optimal path faster than uninformed searches by using
the heuristic to explore most promising paths first.

LINES 38-40: INITIALIZE PRIORITY QUEUE
================================================================================

Line: priority_queue<pair<int, int>, vector<pair<int, int>>, greater<pair<int, int>>> pq;

What it does: Create min-heap priority queue
Structure breakdown:
  - pair<int, int>: Stores (f_cost, node)
  - vector<pair<int, int>>: Container type
  - greater<pair<int, int>>: Comparator for min-heap

Behavior:
  - pq.top(): Returns pair with SMALLEST f_cost
  - pq.push({cost, node}): Adds element maintaining heap order
  - pq.pop(): Removes element with smallest f_cost

Why min-heap: A* always expands node with lowest f(n) = g(n) + h(n)
This is the KEY to A* - always explore most promising path first

Line: g_cost[start] = 0;
What it does: Set cost to reach start node as zero
Why: Distance from start to itself is 0
Logic: We begin at start, so g(start) = 0

Line: pq.push({g_cost[start] + heuristic[start], start});
What it does: Add start node to priority queue
Calculation: f(start) = g(start) + h(start) = 0 + h(start)
Example: If h(start) = 5, pushes {5, 0} to queue
Why: Initialize search from starting point

LINES 66-78: UPDATE COSTS AND ADD TO QUEUE (CORE A* UPDATE)
================================================================================

Line: int new_g_cost = g_cost[node] + wt;
What it does: Calculate cost to reach neighbor through current node
Explanation:
  - g_cost[node]: Cost to reach current node from start
  - wt: Cost of edge from current to neighbor
  - new_g_cost: Total cost from start → current → neighbor
Example: g_cost[1] = 3, wt = 2, then new_g_cost = 5

Line: if (new_g_cost < g_cost[ch])
What it does: Check if this path to neighbor is better than previous best
Comparison:
  - new_g_cost: Cost via current path
  - g_cost[ch]: Previously known best cost (INF if never reached)
Logic: Only update if we found shorter path

Line: g_cost[ch] = new_g_cost;
What it does: Update neighbor's g-cost to this better value
Why: Found cheaper way to reach this neighbor
Example: g_cost[2] = 10 → found path with cost 7 → g_cost[2] = 7

Line: parent[ch] = node;
What it does: Record that we reached neighbor from current node
Purpose: Path reconstruction later
Example: parent[2] = 1 means "reached node 2 from node 1"
Result: Can trace back from goal to start using parent array

Line: int f_cost = g_cost[ch] + heuristic[ch];
What it does: Calculate f(n) = g(n) + h(n) for neighbor
Breakdown:
  - g_cost[ch]: Actual cost from start to neighbor (known)
  - heuristic[ch]: Estimated cost from neighbor to goal (heuristic)
  - f_cost: Total estimated cost: start → neighbor → goal
Example: g_cost[2] = 7, heuristic[2] = 4, f_cost = 11

Line: pq.push({f_cost, ch});
What it does: Add neighbor to priority queue with f-cost
Format: {total_estimated_cost, node_index}
Example: pq.push({11, 2}) means "node 2 with total estimate 11"
Effect: Queue automatically maintains order (smallest f-cost first)

Why this works: A* explores nodes in order of most promising total path
- Low f(n) = close to start + estimated close to goal = likely on optimal path
- Priority queue ensures we always expand lowest f(n) next

================================================================================
HOW A* ALGORITHM WORKS - COMPLETE FLOW
================================================================================

INITIALIZATION:
1. Read graph structure (nodes, edges, weights)
2. Read heuristic values for each node (h(n))
3. Read start and goal nodes
4. Initialize:
   - g_cost[start] = 0 (cost to reach start is 0)
   - g_cost[others] = INF (unknown distance)
   - Add start to priority queue with f = g + h

MAIN LOOP (Expand most promising nodes):
  
  STEP 1: Get node with lowest f(n)
    - Extract from priority queue (min-heap)
    - This is the node with lowest total estimated cost
  
  STEP 2: Check if already visited
    - If yes: Skip (already found optimal path to it)
    - If no: Mark as visited and continue
  
  STEP 3: Check if goal reached
    - If yes: Stop! Found optimal path
    - A* guarantees this is shortest path
  
  STEP 4: Explore neighbors
    For each neighbor of current node:
      
      a) Skip if already visited
      
      b) Calculate new g-cost via current node:
         new_g = g_cost[current] + edge_weight
      
      c) If new_g < g_cost[neighbor]:
         - Found better path to neighbor
         - Update g_cost[neighbor] = new_g
         - Update parent[neighbor] = current
         - Calculate f(neighbor) = g(neighbor) + h(neighbor)
         - Add to priority queue with f-cost
  
  STEP 5: Repeat until goal found or queue empty

PATH RECONSTRUCTION:
1. Start at goal node
2. Follow parent pointers backward to start
3. Reverse the path
4. Output: Start → ... → Goal


================================================================================
KEY CONCEPTS EXPLAINED
================================================================================

G-COST (Actual Cost):
- g(n) = actual shortest distance from start to node n
- Known value (calculated during search)
- Increases as we move away from start
- g(start) = 0, g(goal) = shortest path length

H-COST (Heuristic - Estimated Cost):
- h(n) = estimated distance from node n to goal
- Provided as input (domain knowledge)
- Never changes during search
- Should be admissible: never overestimate actual distance
- h(goal) = 0 (at goal, distance to goal is 0)

F-COST (Total Estimated Cost):
- f(n) = g(n) + h(n)
- Total estimated cost: start → n → goal
- g(n): known cost to reach n
- h(n): estimated remaining cost to goal
- A* always expands node with lowest f(n)

PRIORITY QUEUE:
- Stores nodes waiting to be expanded
- Ordered by f-cost (lowest first)
- Same node can appear multiple times
- Always process node with lowest f(n)
- This is why A* is efficient


================================================================================
WHY A* IS OPTIMAL AND EFFICIENT
================================================================================

OPTIMALITY:
If heuristic is admissible (never overestimates):
- A* guaranteed to find shortest path
- When goal reached, it's via optimal route
- No need to continue searching

EFFICIENCY:
- Heuristic guides search toward goal
- Avoids exploring unpromising directions
- Much faster than uninformed search (BFS, Dijkstra)
- Only explores necessary nodes

COMPARISON:
- BFS: Explores all nodes at distance d before d+1 (no heuristic)
- Dijkstra: Explores by actual cost g(n) only (no goal knowledge)
- A*: Explores by g(n) + h(n) (uses goal knowledge efficiently)

EXAMPLE RUN TRACE
================================================================================

Graph:
  A --3-- B --2-- D
  |       |       |
  5       1       4
  |       |       |
  C ------E ------F (Goal)
        2      3

Heuristics (straight-line distance to F):
  A: 7, B: 5, C: 6, D: 3, E: 3, F: 0

Start: A, Goal: F

INITIALIZATION:
- g_cost[A] = 0, others = INF
- pq = [{7, A}]  (f = 0 + 7)

ITERATION 1: Expand A
- Pop: A (f=7)
- Neighbors: B, C
- B: g=3, h=5, f=8, pq.push({8, B})
- C: g=5, h=6, f=11, pq.push({11, C})
- pq = [{8, B}, {11, C}]

ITERATION 2: Expand B
- Pop: B (f=8)
- Neighbors: A(visited), D, E
- D: g=3+2=5, h=3, f=8, pq.push({8, D})
- E: g=3+1=4, h=3, f=7, pq.push({7, E})
- pq = [{7, E}, {8, D}, {11, C}]

ITERATION 3: Expand E
- Pop: E (f=7)
- Neighbors: B, C, F
- F: g=4+3=7, h=0, f=7, pq.push({7, F})
- pq = [{7, F}, {8, D}, {11, C}, ...]

ITERATION 4: Expand F
- Pop: F (f=7)
- F == goal → STOP!

PATH RECONSTRUCTION:
- parent[F] = E
- parent[E] = B
- parent[B] = A
- parent[A] = -1
- Path: A → B → E → F
- Distance: 7

================================================================================
ADMISSIBLE HEURISTIC
================================================================================

DEFINITION:
A heuristic h(n) is admissible if it never overestimates the actual cost
to reach the goal from node n.

Mathematically: h(n) ≤ actual_cost(n, goal)

EXAMPLES:

Good (Admissible):
- Straight-line distance (never longer than actual path)
- Manhattan distance in grid (counts minimum moves)
- Zero (always admissible but not helpful)

Bad (Not Admissible):
- Overestimated distances
- Would cause A* to miss optimal path

WHY IT MATTERS:
- Admissible heuristic → A* finds optimal path
- Non-admissible → A* might find suboptimal path
- Better heuristic → Fewer nodes explored → Faster


================================================================================
COMMON VARIATIONS
================================================================================

A* WITH DIFFERENT HEURISTICS:
1. Manhattan distance (grid-based problems)
2. Euclidean distance (straight-line distance)
3. Chebyshev distance (diagonal moves allowed)
4. Custom domain-specific heuristics

WEIGHTED A* (WA*):
- f(n) = g(n) + w * h(n), where w > 1
- Trades optimality for speed
- Finds "good enough" paths faster

IDA* (Iterative Deepening A*):
- Space-efficient version
- Uses depth-first search with iterative deepening
- Better for memory-constrained environments


================================================================================
TIME AND SPACE COMPLEXITY
================================================================================

TIME COMPLEXITY:
- Worst case: O(b^d) where b = branching factor, d = depth
- Average case: Much better with good heuristic
- Best case: O(d) with perfect heuristic

SPACE COMPLEXITY:
- O(b^d) for storing nodes in priority queue
- Can grow large for big graphs
- Trade-off: Better heuristic = less space needed

COMPARED TO OTHER ALGORITHMS:
- BFS: O(b^d) time, O(b^d) space
- Dijkstra: O((V+E)log V) time
- A*: Often faster than both with good heuristic


================================================================================
PRACTICAL TIPS
================================================================================

CHOOSING HEURISTIC:
1. Must be admissible (never overestimate)
2. Closer to actual cost = better performance
3. Easier to compute = faster per node
4. Domain knowledge helps

WHEN TO USE A*:
✓ Have good admissible heuristic
✓ Need optimal path
✓ Can afford space for priority queue
✓ Graph is large (A* outperforms BFS/Dijkstra)

WHEN NOT TO USE A*:
✗ No good heuristic available (use Dijkstra)
✗ Any path acceptable (use BFS)
✗ Memory very limited (use IDA*)
✗ Very small graph (overhead not worth it)
