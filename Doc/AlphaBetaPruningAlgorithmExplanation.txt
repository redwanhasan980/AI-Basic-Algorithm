WHAT IS ALPHA-BETA PRUNING?
----------------------------
Alpha-Beta Pruning is an optimization technique for the Minimax algorithm.
It reduces the number of nodes evaluated in the game tree by eliminating
branches that cannot possibly influence the final decision.

Think of it like this: If you're choosing the best restaurant and you've 
already found one that costs $10, you don't need to keep reading the menu 
of a restaurant where the cheapest item is $50.


BASIC CONCEPTS YOU NEED TO UNDERSTAND
--------------------------------------

1. GAME TREE
   - A tree structure representing all possible moves in a game
   - Each node is a game state (board configuration)
   - Each branch is a possible move
   - Leaf nodes are terminal states (win/lose/draw)

2. MINIMAX ALGORITHM
   - Two players: Maximizer (AI trying to win) and Minimizer (opponent)
   - Maximizer wants the highest score
   - Minimizer wants the lowest score
   - They alternate turns going down the tree

3. ALPHA AND BETA VALUES
   - Alpha: The best value the Maximizer can guarantee so far
   - Beta: The best value the Minimizer can guarantee so far
   - Initially: Alpha = negative infinity, Beta = positive infinity
   - As we search, these values get updated and converge


THE MAGIC OF PRUNING
---------------------
Pruning happens when we realize: "No matter what happens in this branch,
it won't change our decision." So we stop exploring that branch.

Two types of cutoffs:

1. ALPHA CUTOFF (at Minimizer level)
   - If the Minimizer finds a move that gives a score <= Alpha
   - The Maximizer already has a better option elsewhere
   - No point continuing this branch
   
2. BETA CUTOFF (at Maximizer level)
   - If the Maximizer finds a move that gives a score >= Beta
   - The Minimizer already has a better option elsewhere
   - No point continuing this branch


STEP-BY-STEP ALGORITHM EXPLANATION
===================================

PART 1: THE MAIN STRUCTURE
---------------------------

Step 1: Create the basic game board
   - Define a 3x3 grid for Tic-Tac-Toe
   - Use a 2D array: board[3][3]
   - Empty cells contain a space character ' '
   - Player X (AI) and Player O (Human) mark their moves

Step 2: Initialize the board
   - Loop through all rows (0 to 2)
   - Loop through all columns (0 to 2)
   - Set each cell to empty ' '

Step 3: Display the board
   - Print the board in a readable format with lines
   - Show row by row with separators (---|---|---)


PART 2: GAME STATE EVALUATION
------------------------------

Step 4: Create a function to check for a winner
   - Check all 3 rows: Are all cells in a row the same?
   - Check all 3 columns: Are all cells in a column the same?
   - Check both diagonals: Are all cells in a diagonal the same?
   - If someone won, return their symbol ('X' or 'O')
   - If no empty cells remain, return 'D' for draw
   - Otherwise, return ' ' meaning game continues

Step 5: Understand the scoring system
   - If AI (X) wins: return +1
   - If Human (O) wins: return -1
   - If draw: return 0
   - These scores guide the AI's decisions


PART 3: THE ALPHA-BETA FUNCTION (THE CORE!)
--------------------------------------------

Step 6: Create the alphabeta function
   Parameters needed:
   - alpha: Best score for Maximizer so far (start at -infinity)
   - beta: Best score for Minimizer so far (start at +infinity)
   - isMaximizing: Boolean - is it AI's turn (true) or opponent's (false)?

Step 7: Check if game is over (base case)
   - Call the check winner function
   - If AI wins, return +1
   - If Human wins, return -1
   - If draw, return 0
   - These are terminal nodes - no more recursion needed

Step 8: Handle the MAXIMIZER's turn (AI trying to win)
   
   8a. Initialize bestScore to negative infinity
       - We want to find the maximum, so start with worst possible value
   
   8b. Loop through all cells on the board
       - Go row by row (i from 0 to 2)
       - Go column by column (j from 0 to 2)
   
   8c. For each empty cell:
       - Place AI's mark (X) in that cell
       - Recursively call alphabeta with:
         * Same alpha and beta values
         * isMaximizing = false (now it's opponent's turn)
       - Remove the mark (undo the move) - backtracking
       - Update bestScore to be the maximum of current bestScore and returned score
       - Update alpha to be the maximum of alpha and bestScore
   
   8d. THE PRUNING PART (Beta cutoff)
       - After updating alpha, check: Is beta <= alpha?
       - If YES: The Minimizer won't choose this path anyway
       - Return bestScore immediately (prune remaining branches)
       - This is the optimization - we skip checking other moves
   
   8e. After checking all moves (or pruning)
       - Return the bestScore

Step 9: Handle the MINIMIZER's turn (Opponent trying to minimize AI's score)
   
   9a. Initialize bestScore to positive infinity
       - We want to find the minimum, so start with worst possible value
   
   9b. Loop through all cells on the board
       - Go row by row (i from 0 to 2)
       - Go column by column (j from 0 to 2)
   
   9c. For each empty cell:
       - Place opponent's mark (O) in that cell
       - Recursively call alphabeta with:
         * Same alpha and beta values
         * isMaximizing = true (now it's AI's turn)
       - Remove the mark (undo the move) - backtracking
       - Update bestScore to be the minimum of current bestScore and returned score
       - Update beta to be the minimum of beta and bestScore
   
   9d. THE PRUNING PART (Alpha cutoff)
       - After updating beta, check: Is beta <= alpha?
       - If YES: The Maximizer won't choose this path anyway
       - Return bestScore immediately (prune remaining branches)
       - This is the optimization - we skip checking other moves
   
   9e. After checking all moves (or pruning)
       - Return the bestScore


PART 4: AI MOVE SELECTION
--------------------------

Step 10: Create the AI move function
   
   10a. Initialize variables:
        - bestScore to negative infinity (we want maximum)
        - moveRow to -1 (will store the row of best move)
        - moveCol to -1 (will store the column of best move)
   
   10b. Loop through all cells on the board
        - Check each row (i from 0 to 2)
        - Check each column (j from 0 to 2)
   
   10c. For each empty cell:
        - Place AI's mark (X) temporarily
        - Call alphabeta with:
          * alpha = negative infinity (no lower bound initially)
          * beta = positive infinity (no upper bound initially)
          * isMaximizing = false (evaluate opponent's response)
        - Remove the mark (undo)
        - If this score is better than bestScore:
          * Update bestScore
          * Save this position as moveRow and moveCol
   
   10d. Make the final move
        - Place AI's mark at the best position found: board[moveRow][moveCol]
        - Print the move to show the user


PART 5: HUMAN MOVE INPUT
-------------------------

Step 11: Create the human move function
   
   11a. Start an infinite loop (we'll break when move is valid)
   
   11b. Ask the user for input
        - Prompt: "Your move (row col): "
        - Read row number
        - Read column number
   
   11c. Validate the move
        - Is row between 0 and 2?
        - Is column between 0 and 2?
        - Is that cell empty (contains ' ')?
   
   11d. If valid:
        - Place human's mark (O) at that position
        - Break out of the loop
   
   11e. If invalid:
        - Print error message
        - Loop continues, ask for input again


PART 6: GAME LOOP (MAIN FUNCTION)
----------------------------------

Step 12: Set up the game
   - Initialize the empty board
   - Print welcome messages and instructions
   - Display the initial empty board

Step 13: Create the main game loop
   
   13a. Human's turn:
        - Call the human move function
        - Display the updated board
        - Check if game is over:
          * If human won, print "You win!" and exit loop
          * If draw, print "It's a draw!" and exit loop
          * If AI won (shouldn't happen here), print "AI wins!" and exit loop
   
   13b. AI's turn:
        - Print "AI is thinking..."
        - Call the AI move function
        - Display the updated board
        - Check if game is over:
          * If AI won, print "AI wins!" and exit loop
          * If draw, print "It's a draw!" and exit loop
          * If human won (shouldn't happen here), print "You win!" and exit loop
   
   13c. If no one won:
        - Loop continues, back to human's turn

Step 14: End the program
   - After the game loop ends, program terminates


KEY DIFFERENCES FROM REGULAR MINIMAX
=====================================

WITHOUT Alpha-Beta Pruning:
- Must evaluate EVERY possible move
- Explores the entire game tree
- Very slow for complex games

WITH Alpha-Beta Pruning:
- Skips branches that won't affect the decision
- Uses Alpha and Beta to track boundaries
- When Beta <= Alpha, stop exploring that branch
- Same result as Minimax, but much faster
- Can reduce nodes evaluated by 40-60% or more


VISUAL EXAMPLE OF PRUNING
==========================

Imagine this scenario:

Level 1 (Maximizer):
   Move A evaluated: Score = 5
   Now evaluating Move B:
      Level 2 (Minimizer):
         Option B1: Score = 3
         Option B2: Score = 2
         Option B3: Not checked! (PRUNED)
         
Why was B3 pruned?
- The Maximizer already has Move A with score 5
- The Minimizer at B is choosing between 3, 2, and potentially less
- Even if B3 is 10, the Minimizer will choose 2 or 3 (not 10)
- So Move B can never beat Move A (score 5)
- No point checking B3!


IMPORTANT IMPLEMENTATION DETAILS
=================================

1. INTEGER LIMITS
   - Use -INT_MAX for negative infinity
   - Use INT_MAX for positive infinity
   - These represent the worst possible scores for each player

2. BACKTRACKING
   - After trying a move, ALWAYS undo it
   - board[i][j] = 'X';  // Try move
   - score = alphabeta(...);  // Evaluate
   - board[i][j] = ' ';  // UNDO move - this is critical!

3. ALPHA-BETA UPDATES
   - Maximizer: alpha = max(alpha, score)
   - Minimizer: beta = min(beta, score)
   - Check for pruning AFTER updating

4. PRUNING CONDITION
   - Always check: if (beta <= alpha) then prune
   - This works for both maximizer and minimizer levels
   - Return immediately when this condition is true

5. RECURSION STRUCTURE
   - Maximizer calls Minimizer
   - Minimizer calls Maximizer
   - They alternate until reaching terminal state
   - Each level passes updated alpha and beta down the tree


COMMON MISTAKES TO AVOID
=========================

1. Forgetting to undo moves (backtracking)
   - Always restore board state after trying a move

2. Wrong pruning condition
   - It's beta <= alpha, NOT alpha >= beta (same thing but easy to confuse)

3. Not updating alpha and beta correctly
   - Maximizer updates alpha (going up)
   - Minimizer updates beta (going down)

4. Pruning before updating alpha/beta
   - Update first, THEN check pruning condition

5. Using the wrong initial values for alpha/beta
   - Start with -infinity for alpha, +infinity for beta

6. Confusing which player is which
   - Keep track: isMaximizing true = AI, false = opponent


HOW TO TEST YOUR IMPLEMENTATION
================================

1. Play against the AI
   - It should never lose (will win or draw)
   - If you can beat it, there's a bug

2. Let AI make first move
   - It often chooses corner or center
   - These are optimal opening moves

3. Try to set up obvious wins
   - AI should block your winning moves
   - AI should take its own winning moves

4. Compare with regular Minimax
   - Both should make identical moves
   - Alpha-Beta should be faster


COMPLEXITY ANALYSIS
===================

Time Complexity:
- Worst case: O(b^d) - same as Minimax
- Best case: O(b^(d/2)) - significant improvement
- Average case: Usually 40-60% reduction

Where:
- b = branching factor (average number of moves per position)
- d = depth of the tree (number of moves until game ends)

Space Complexity:
- O(d) for recursion stack
- Same as Minimax


CONCLUSION
==========

Alpha-Beta Pruning is essentially "smart Minimax":
1. It explores the game tree like Minimax
2. But it's clever enough to skip useless branches
3. It guarantees the same optimal result
4. But does it much faster

The key insight: If you already have a good enough option, you don't
need to explore branches that provably can't beat it.

Alpha and Beta act like a "window" of interesting scores. When we find
a score outside this window (in the wrong direction), we know that
branch won't be selected, so we prune it.
