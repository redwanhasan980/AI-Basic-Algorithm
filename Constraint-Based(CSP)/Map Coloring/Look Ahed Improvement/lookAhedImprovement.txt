Use the current partial assignment to look ahead and eliminate impossible values from the remaining variables' domains.
unlike the Heuristic improvement which only 
consider in the current time which variable to chose.
The look ahead improvement will consider the future impact of the current choice.
For example, if we have a variable A with domain {1, 2, 3} and we assign A = 1,
we will look ahead to see how this assignment affects the domains of the neighboring variables.
and a neighbor variable B has domain {1, 2}, we will eliminate 1 from B's domain,
resulting in B's domain being reduced to {2}. This helps to prevent future conflicts and    
reduces the search space.

Steps to implement Look Ahead Improvement (Forward Checking):

Step 1: Select a variable
Pick an unassigned variable Xi.
(You can use smart selection like MRV - pick the variable with fewest remaining values)

Step 2: Assign a value
Choose a value v from Xi's available domain and assign it to Xi.

Step 3: Forward check (look-ahead pruning)
For every unassigned neighbor Xj that is connected to Xi:
- Check each value vj in Xj's domain
- If assigning Xi = v and Xj = vj breaks any rule (like same color for neighbors),
  then remove vj from Xj's domain
- If Xj's domain becomes empty (no values left),
  it means there's no valid choice for Xj
  → Undo the assignment on Xi and backtrack immediately

Step 4: Recursive call
If all neighbors still have at least one valid value in their domains:
→ Move to the next variable and repeat the process
If any neighbor has an empty domain (dead-end detected):
→ Backtrack and try a different value for Xi

Step 5: Backtrack when necessary
If all possible values for Xi have been tried and none work:
→ Go back to the previous variable and try a different value for it

Step 6: Continue until
Either a complete solution is found (all variables assigned successfully), or
All possibilities are tried (no solution exists)


Steps of Arc Consistency (AC-3) Integration:

What is Arc Consistency?
An arc (X, Y) is consistent if for every value in X's domain, there exists at least 
one value in Y's domain that satisfies the constraint between them.
Arc consistency is stronger than forward checking because it propagates constraints 
through the entire network, not just immediate neighbors.

Step 1: Initialize the Queue
Create a queue Q containing all arcs (ordered pairs of connected variables)
For a graph with edges, if Node A connects to Node B:
- Add arc (A, B) to the queue
- Add arc (B, A) to the queue (because constraints work both ways)

Step 2: Process Each Arc
While the queue is not empty:
- Remove an arc (Xi, Xj) from the front of the queue
- Check if this arc needs revision

Step 3: Revise the Arc (Xi, Xj)
For each value vi in Xi's domain:
- Check if there exists at least one value vj in Xj's domain where vi ≠ vj
- If NO such value exists (meaning vi conflicts with all values in Xj's domain):
  → Remove vi from Xi's domain
  → Mark that Xi's domain was revised

Step 4: Check for Empty Domain
If Xi's domain becomes empty after revision:
→ Return FAILURE (no solution possible from this state)
→ This is the power of AC-3: it detects impossibility early!

Step 5: Propagate Changes
If Xi's domain was revised (some values were removed):
- For every neighbor Xk of Xi (except Xj):
  → Add the arc (Xk, Xi) back to the queue
  → This ensures the change propagates throughout the network

Step 6: Success
If the queue becomes empty and no domain is empty:
→ Arc consistency is achieved
→ Continue with the search (assign next variable)

Step 7: Integration with Backtracking
Before assigning a value to a variable:
1. Make the assignment
2. Reduce the variable's domain to just that one value
3. Run AC-3 to propagate constraints
4. If AC-3 succeeds: continue to next variable
5. If AC-3 fails: backtrack immediately (no need to explore further)

Why AC-3 is Powerful:
- Forward Checking only checks direct neighbors (1 level)
- AC-3 propagates through the entire constraint network (multiple levels)
- Detects dead-ends earlier, prunes more branches
- More computation per node, but explores fewer nodes overall

Example:
Graph: A--B--C--D (linear chain)
If we assign A = Red:
- Forward Checking: Only checks B, removes Red from B's domain
- AC-3: Checks B, then propagates to C, then to D
  If this causes any domain to empty, we know immediately it won't work

Time Complexity:
- O(ed³) where e = number of arcs, d = domain size
- Each arc can be added to queue at most d times
- Each revision takes O(d²) time
